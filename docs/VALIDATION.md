# Validation of 0.4.0

- JavaScript tests: 27 passing. Python tests: 17 passing.
- Build, ESLint and formatting checks pass. The included browser bundle activates through DSH's module loader and settings slot.
- In an isolated DSH 0.2.1-rc.2 Web profile: imported the retained Gyro S GGUF through the host file picker, created the model automatically, selected a 65,536-token context, opened the projector picker and selected an existing Flash-Next FP16 mmproj, and saved both choices.
- Official Strata v0.2.7 / Control and engine 0.1.52 were downloaded and their archive checksums verified. Gyro S loaded through the DSH adapter at 32,768 context, FP16/FP16, without manual worker, PCIe or environment overrides, and answered `2 + 2` with `4`. Native IQ startup requires `--spec 2` or greater as well as enabled prefill; the adapter uses the minimum valid verifier and automatic allocation.
- Real engine help was inspected for regular Strata and the local TQP fork. The former advertised three of the requested KV pairs; the fork advertised all seven. Unsupported choices are not silently mapped to other formats.
- Synthetic GGUF tests cover cross-directory shards, duplicates, missing shards, selected-file imports, component roles and malformed headers. Filesystem tests cover actual directory navigation and missing paths.
- A live native Thorough integration request with a short test budget completed in 85.7 seconds, confirmed the baseline, and saved a real preset. The plugin’s upstream preset bridge subsequently resolved it as fresh and applied it successfully. This is an integration check, not a full optimization sweep.
- Native tuning tests check the actual argument vector: Thorough mode with no plugin goal, RAM, answer-difference or repeatability overrides. Previous separate validation included a bounded native Thorough run which saved a preset; that was not a completed two-hour optimization sweep.

These checks do not establish image-generation quality, numerical compatibility of arbitrary projector/model pairs, or performance for every KV format and context. Strata remains responsible for validating a selected setup and measuring it with its own tuner. Gyro L also loaded through the adapter with its TQP fork at 32,768 context and FP16/FP16, without manual performance or environment overrides, and answered the same prompt with `4`. Its first cold load spent several minutes reading the model drive; this was a functional generation check, not a tuned speed benchmark. The previously retained Gyro L and Gyro S benchmark reports are separate from this UI and importer validation.

# Validation of 0.5.0

- Wrapper: 34 JavaScript tests and 17 Python tests passed; browser build, ESLint and formatting checks passed. Tests exercise per-model budgets, LRU order after reopening the cache, oversized snapshots, path/symlink boundaries, native checkpoint dispatch, queued model switching and purge waiting for an active answer while retaining original files.
- An isolated DSH 0.2.1-rc.2 Web profile imported the self-contained tarball with the native plugin installer and enabled it. The provider displayed the included Strata runtime, working Import files and the single top-level Purge all cache control. A server restart without reloading the browser preserved owner access: the file picker opened and listed host directories. An unauthenticated request to the plugin endpoint returned 401.
- GPU: NVIDIA RTX PRO 5000 Blackwell Generation Laptop GPU, sm_120. Engines built with CUDA 13.1. The official v0.2.7 engine and retained TQP fork include the optional-draft checkpoint patch recorded under vendor. Their native conversation snapshot regression executables passed 4,363 and 4,209 checks respectively. HIP, SYCL and other CUDA architectures were not built or tested.
- A real offline-dependency integration test used the installed package's portable Python, Control, GGUF helper and both bundled engines. Proxy settings rejected external downloads. Gyro S was prepared through the included helper. Gyro L reused its existing compatible pack. Each ran at 32,768 context and FP16/FP16, with native automatic prefill/expert-cache allocation and a two-token verifier window, without numeric worker/PCIe/environment performance overrides. Tuning presets were disabled to isolate native defaults.
- In the sequence Gyro S → Gyro L → Gyro S, all three answers to `2 + 2` were `4`. Both models wrote native SSD snapshots, approximately 228 MiB each for these short prompts. Switching back to S restored 103 tokens. After disposing the service and starting a separate Node process, S again restored 103 tokens and answered `4`. A separate fresh-process Gyro L run restored 99 tokens and answered `4`. This tests process restart recovery; the host was not rebooted.
- Live purge validation loaded a real native Gyro S server, invoked the cache action, and confirmed that the model was unloaded, the checkpoint directories removed, both saved profiles retained and original model size/mtime unchanged. GPU memory returned to its idle baseline after testing.
- Native SAVE initially failed without an MTP draft (`invalid K/V extent`). The bundled patch omits only an unallocated draft from session serialization, read limits and restore. Native regression cases retain the existing main/MTP round trip and add a no-draft round trip. Tensor math and tuning policy are unchanged by this patch.

These checks establish functional loading, native save/restore and cache bookkeeping for the stated configurations. They do not establish tuned speed, a full Thorough sweep, every KV/context combination, vision quality or accelerated weight loading. Mixed KV disk snapshots remain unsupported by the fork. A 16 GiB budget is exercised with small synthetic limits rather than filling 16 GiB of the user's disk. Previous benchmark reports and the bounded Thorough integration result above are retained separately.

# Validation of 0.5.1

- 37 JavaScript and 17 Python tests passed, with browser build, lint and formatting checks. New coverage includes exact request bodies for all four labels, projection compatibility, separate checkpoint namespaces, native context defaults and non-step native context sizes.
- An isolated DSH 0.2.1-rc.2 profile installed the self-contained archive offline. Its conversation picker displayed exactly Low, Medium, High and Uncensored. The editor selected Native (262,144 tokens), with smaller context values still available in 32,768-token increments. The original user's running profile was not restarted for this test.
- Gyro S ran Low → Medium → High → Uncensored → High at 262,144 context and FP16/FP16. Gyro L ran High → Uncensored → High at the same context and precision. Every benign arithmetic test returned `4`, with the same server process across each sequence. Native engine logs confirmed that the control vector loaded in project/per-layer mode over layers 4–44. The engines and their tuning policy are unchanged from 0.5.0.
- Fresh-process Gyro S tests restored 99 tokens from the Uncensored checkpoint and 103 tokens from the High checkpoint at native context. Each returned `4`; native session files retained their correct projection mode.
- The supplied vector's checksum matches the original official Control archive. No vector was created or trained for this plugin. No refusal-rate, safety-quality or broad language-quality benchmark was performed; Uncensored is a selectable experimental preset, not a guarantee about every answer.

The compatible 0.5.0 runtime ABI is reused by 0.5.1. An already running 0.5.0 model must be unloaded and loaded once after the plugin update; changing the new presets thereafter is per request. New imports default to native context. Existing explicit saved contexts are retained until Native is selected.
